# 古文岛唐诗候选标题消歧设计

## 目标

修复古文岛 320 首唐诗候选中两组“同题同作者”记录无法区分的问题，同时保留
四首正文不同的作品。

修复后：

- 唐诗候选总数保持 320；
- 每条候选的稳定 ID、导入键、来源 ID 和来源哈希保持不变；
- “作者 + 展示标题”在候选集中唯一；
- 已入库的四条记录通过管理 API 定向修订，不删除后重新导入。

## 问题确认

当前重复检测按“作者 + 标题”发现两组冲突：

| 作者 | 原始标题 | 来源 ID | 首句 |
| --- | --- | --- | --- |
| 李商隐 | 无题二首·其一 | `2d27cb0ecae4` | 凤尾香罗薄几重 |
| 李商隐 | 无题二首·其一 | `05c6c4ccf634` | 昨夜星辰昨夜风 |
| 李商隐 | 隋宫 | `0c472e85a3ad` | 乘兴南游不戒严 |
| 李商隐 | 隋宫 | `09fd71c77ec7` | 紫泉宫殿锁烟霞 |

四条记录的正文、来源 ID 和来源 URL 均不同，因此它们不是重复抓取记录，不能
通过删除候选解决。

根因是转换器保留了规范标题，却没有为同题同作者的不同作品生成唯一展示标题。
现有制品测试只校验内容 ID 和导入键唯一，没有覆盖运营界面使用的“作者 + 标题”
身份。

## 标题消歧规则

转换器先解析并校验全部 320 条源记录，再按 NFC 规范化后的
`author + title` 分组。

- 分组只有一条记录时，`payload.title` 保持原始标题。
- 分组包含多条记录时，使用首句的第一个分句作为消歧词。
- 展示标题格式固定为 `原始标题（消歧词）`。
- 消歧词从第一行开头截取到首个 `，`、`。`、`！`、`？`、`；` 或 `：`，
  去除首尾空白和结尾标点。
- 生成后再次校验 `author + payload.title` 唯一；若仍冲突则生成失败，不写出
  新制品。

本次四条记录映射为：

- `无题二首·其一（凤尾香罗薄几重）`
- `无题二首·其一（昨夜星辰昨夜风）`
- `隋宫（乘兴南游不戒严）`
- `隋宫（紫泉宫殿锁烟霞）`

此规则只改变冲突组。其余 316 首的展示标题保持不变。

## 版本与身份

转换规则版本从 `guwendao-tang-poem-v1` 升级为
`guwendao-tang-poem-v2`，用于标识标题映射行为已经改变。

以下身份字段保持不变：

- `id = sc-gwd-<sourceId>`
- `importKey = GUWENDAO_TANG:<sourceId>`
- `sourceRef`
- `payload.source.sourceId`
- `payload.source.sourceUrl`
- 基于规范源记录计算的 `sourceHash`

来源哈希描述外部源记录，不包含派生展示标题，因此不因本次消歧而变化。

## 制品更新

重新生成：

`frontend/content/candidates/poems-guwendao-tang-320.ndjson`

生成结果必须满足：

- 恰好 320 行；
- ID 和导入键各自唯一；
- `author + payload.title` 唯一；
- 只有四条 `payload.title` 相比 v1 发生变化；
- 所有记录使用 `guwendao-tang-poem-v2`；
- 制品 SHA-256 更新并由仓库测试锁定。

原始外部源文件不修改。

## 数据库修订

现有原始导入链路按稳定内容 ID 跳过已存在记录，因此重新导入 v2 制品不能更新
已入库标题。

使用现有受鉴权的内容管理接口：

`PATCH /v1/admin/content/items/{id}?expectedRevision=1`

分别更新四条记录。请求保留当前等级、难度、晋级要求、标签、作者、正文、
`charRefs` 和来源元数据，只替换标题。

每条记录从 revision 1 更新到 revision 2，并产生正常的内容审计记录。不得直接
执行 SQL 更新。

不需要创建新的候选导入批次。已有导入批次继续描述初始 v1 导入；内容修订审计
描述本次标题修复。

## 错误处理

- 源记录数量、来源 ID、正文或 URL 校验失败时，生成终止。
- 冲突记录没有可用首句分句时，生成终止。
- 消歧后仍存在“作者 + 展示标题”冲突时，生成终止。
- 制品生成继续使用原子替换，失败时保留旧文件。
- 数据库修订使用乐观锁；revision 不匹配时停止并重新读取，不覆盖并发修改。
- 任一 API 更新失败时记录已完成和未完成 ID，修复后从剩余记录继续。

## 测试

纯转换器测试覆盖：

- 非冲突标题保持不变；
- 同题同作者记录按首句消歧；
- 不同作者的同题作品不触发消歧；
- 首句分句提取和 Unicode 规范化；
- 无法生成唯一展示标题时拒绝输出；
- v2 规则版本、稳定身份和来源哈希。

仓库制品测试覆盖：

- 320 条候选边界不变；
- `author + payload.title` 全部唯一；
- 四个预期标题存在；
- 旧的四个歧义标题不再出现；
- 新制品 SHA-256 固定。

数据库验收覆盖：

- `POEM / DRAFT` 仍为 320；
- 四个稳定 ID 仍存在且为 `DRAFT`；
- 四条记录标题符合预期且 revision 为 2；
- 数据库中候选唐诗的“作者 + 标题”无重复；
- 正式古诗 23 条及其修订不变。

## 非目标

- 不删除或合并任何诗作；
- 不修改正式古诗；
- 不补充 `charRefs`、译文、赏析、音频或图片；
- 不修改内容表结构；
- 不改变后台通用内容编辑协议；
- 不将候选激活或发布。
