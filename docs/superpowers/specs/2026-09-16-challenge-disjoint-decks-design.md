# 亲子挑战题目严格去重设计

> 状态：已批准
> 日期：2026-09-16
> 范围：Playground 与 Taro 小程序共用的挑战领域逻辑

## 1. 目标

亲子挑战中，孩子已经回答过的知识点不得再次出现在家长回合。去重以
`knowledgePointId` 为准，因此同一首诗或同一成语即使能生成不同题型，也只能分配给
一位参与者。

## 2. 分配规则

- 先按现有难度顺序、确定性随机种子和可生成题型规则，为孩子与家长分别生成候选牌组。
- 只保留双方均可稳定生成题目的知识点，形成可分配的共同知识点池。
- 按孩子、家长交替取题；每方每次从自己的候选顺序中选择第一个尚未分配的知识点。
- 固定题量竞速每人分配 `questionCount` 道题，双方题量相同。
- 计时模式分完全部共同知识点；总数为奇数时孩子多一道，双方容量差不超过一道。
- 同一个 `challengeId`、配置和语料必须得到完全相同的分配，保证暂停恢复后题目不漂移。

## 3. 容量处理

固定题量竞速要求共同知识点池至少包含 `questionCount * 2` 个知识点。容量不足时，
创建挑战失败，并返回实际可用数量与所需总数量。两端统一提示：

`当前题库只有 N 道，亲子不重复答题至少需要 M 道`

计时模式至少需要两个共同知识点，确保孩子与家长都能获得一道题；否则该挑战维度不可用。

## 4. 兼容性

- 保留 `buildChallengeDeck` 公共接口，内部改为从成对牌组中返回指定参与者牌组。
- 新增 `buildChallengeDecks`，作为双人分配与容量校验的领域入口。
- 挑战规则版本从 `challenge-v4` 升为 `challenge-v5`，旧规则的进行中快照由现有版本校验清除。
- 题目种子仍使用 `challengeId:participant:index` 形式；相同输入下恢复结果稳定。
- 内容版本、答题事件、结算结构和持久化字段不变。

## 5. 测试策略

- 领域牌组测试覆盖跨参与者零交集、固定模式等量、计时模式均衡、难度偏好、语料重排稳定性和容量错误。
- 引擎测试通过完整孩子回合与家长回合验证实际展示题目零交集，并验证同一会话恢复后当前题目一致。
- Playground 集成测试验证发布语料在诗词和成语维度均可提供两组各十道的不重复题。
- Playground 与小程序页面测试验证新的容量不足文案。
- 最终运行领域测试、应用测试、两端页面测试、覆盖率、类型检查和前端全量测试。

## 6. 验收标准

1. 任一挑战内孩子与家长收到的 `knowledgePointId` 集合没有交集。
2. 固定模式双方题量均为配置值；总容量不足时不创建会话。
3. 计时模式双方牌组容量差不超过一道，且不共享知识点。
4. 每位参与者的牌组继续优先采用其目标难度和既有回退顺序。
5. 同一挑战恢复后题序、题型和题目种子不变。
6. Playground 与小程序显示一致且明确的容量错误。
